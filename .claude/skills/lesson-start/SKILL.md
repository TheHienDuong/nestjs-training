# lesson-start

Open a new lesson following the correct process, so all lessons look consistent and no step is ever missed.

## Why this skill is needed

This task is repeated 26 times. Doing it manually will lead to inconsistencies: lesson 3 uses one branch naming style, lesson 12 uses another, notes are missing the "Connect to prior knowledge" section — which is the most important section. Especially, branch names **must** match Linear convention, otherwise you will lose all task status automation (see `docs/adr/0002-linear-as-source-of-truth.md`).

## Input

Lesson code (`L02`) or name (`controllers`). If nothing is provided → get the first ⬜ lesson in `docs/ROADMAP.md`.

## Steps

### 1. Identify the lesson

Read `docs/ROADMAP.md`, find the lesson line. Extract: number, name, phase, related doc links. If it is already ✅ → ask the user if they want to redo it.

### 2. Check current working state

```bash
git status --short && git branch --show-current
```

- Uncommitted changes present → **stop**, notify the user, do not auto-stash.
- Currently on an unmerged lesson branch → ask before switching away.

### 3. Fetch issue from Linear

Use Linear MCP to find the lesson's issue in the corresponding project.- **Issue exists:** retrieve the `identifier` (e.g. `NES-12`), `branchName` (auto-generated by Linear — use this exact string), and description.
- **No existing issue:** create a new one following the description structure in the _Issue description format_ section below, assign the correct project and add the `phase-X` label.
- **Linear MCP is not connected:** notify the user to run `! claude mcp add --transport http linear https://mcp.linear.app/mcp` then `/mcp`. Continue with the remaining steps, use a branch in the format `lesson/XX-ten-lesson`, and note that the Linear linking step is still pending.

### 4. Create branch

```bash
git checkout main && git pull origin main
git checkout -b <branchName from Linear>
```

The branch name **must** be taken directly from the `branchName` field in Linear. Do not create your own — the `nes-XX` string inside is the identifier used by Linear.

### 5. Scaffold lesson note

Copy `docs/templates/lesson-note.md` → `docs/lessons/XX-ten-lesson/README.md`.

Pre-fill: title, metadata table (phase, Linear ID, branch, docs, today's date), and the **🎯 Objectives** section using the issue description. **Leave empty** the Theory / Hands-on / Quiz sections — these will be filled in during the `/teach` and `/lesson-review` steps.

### 6. Generate SPEC.md for the coder agentCopy the original description of the Linear issue into `docs/lessons/XX-ten-lesson/SPEC.md`. This is the only file the Coder agent (codex, or any other tool acting as the Coder) reads to know what to do — it has no MCP access to Linear (see [ADR-0004](../../docs/adr/0004-mcp-single-writer-for-coder-agent.md) and `docs/workflow/AGENT-MODEL.md`). Only Claude is allowed to edit this file; if the Linear issue is updated later, update `SPEC.md` at the same time.

### 7. Move issue to In Progress
Update the issue status via the Linear MCP. (If the GitHub integration is enabled, step 4 will also perform this action automatically — re-running the update is harmless since it uses the same value.)

Note: The Linear update steps (steps 3, 6, 7) can only be performed by Claude Code — the Coder agent (whether it is codex or any other tool) has no MCP connection to Linear (see `docs/workflow/AGENT-MODEL.md`), so it cannot run this skill on its own.

### 8. Report to user
Reply briefly in Vietnamese:
- Which lesson, which branch, where the notes are located, where the `SPEC.md` is located
- Lesson objectives (3–5 bullet points)
- Next command to type: `/teach <topic>`

## Linear issue description format
```markdown
## 🎯 Learning objectives

- <3-5 measurable bullet points>

## 📚 Official documentation

- [<item name>](<full docs.nestjs.com link>)

## 🔗 Link to prior knowledge

- Express/Prisma/hexagonal: <cross-reference>

## 🛠 Hands-on

<what code, in which file, how to verify it>

## ✅ Definition of Done

- [ ] Lesson notes include all sections: Link to prior knowledge + Sources
```- [ ] Hands-on runs successfully
- [ ] Tests pass
- [ ] Pass the quiz at the review step
- [ ] PR has green CI and has been merged
```

## Boundaries

- **Do not** write code in `src/` — this is the lesson opening step, not the implementation step.
- **Do not** commit anything. Only create a branch and a note file.
- **Do not** rename your Linear branch to make it "look nicer".
- `SPEC.md` can only be edited by Claude — the Coder agent (codex or any other tool acting in that role) can only read it.
```
