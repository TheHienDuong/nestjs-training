# lesson-start

Open a new lesson following the correct process, so all lessons look consistent and no step is ever missed.

## Why this skill is needed

This task is repeated 26 times. Doing it manually will lead to inconsistencies: Lesson 3 uses one branch naming style, Lesson 12 uses another, notes are missing the "Connect to prior knowledge" section — which is actually the most important section. Especially, the branch name **must** match the Linear convention, otherwise you will lose all task status automation (see `docs/adr/0002-linear-as-source-of-truth.md`).

## Inputs

Lesson code (`L02`) or name (`controllers`). If nothing is provided → get the first ⬜ lesson in `docs/ROADMAP.md`.

## Steps

### 1. Identify the lesson

Read `docs/ROADMAP.md`, find the lesson line. Extract: number, name, phase, and related doc links. If it is already marked ✅ → ask the user if they want to redo it.

### 2. Check current working state

```bash
git status --short && git branch --show-current
```

- There are uncommitted changes → **stop**, notify the user, do not auto-stash.
- You are on an unmerged different lesson branch → ask before switching away.

### 3. Retrieve the Linear issue

Use Linear MCP to find the lesson's issue in the corresponding project.

- **Issue exists:** get the `identifier` (e.g. `NES-12`), `branchName` (auto-generated by Linear — use this exact string), and description.
- **No issue yet:** create a new one following the description structure in the _Linear issue description format_ section below, assign it to the correct project + add the `phase-X` label.
- **Linear MCP is not connected:** notify the user to run `! claude mcp add --transport http linear https://mcp.linear.app/mcp` then `/mcp`. Continue with the remaining steps, use a branch in the format `lesson/XX-ten-lesson`, and note that the Linear linking step is still pending.

### 4. Create the branch

```bash
git checkout main && git pull origin main
git checkout -b <branchName from Linear>
```

The branch name **must** be taken directly from the `branchName` field in Linear. Do not improvise — the `nes-XX` string inside is what Linear uses for identification.

### 5. Scaffold the lesson note

Copy `docs/templates/lesson-note.md` to `docs/lessons/XX-lesson-name/README.md`.

Pre-fill: the title, metadata table (phase, Linear ID, branch, docs, today's date), and the **🎯 Objectives** section from the issue description. **Leave empty** the Theory / Hands-on / Quiz sections — these are filled in during the `/teach` and `/lesson-review` steps.

### 6. Generate SPEC.md for the coder agent

Copy the full Linear issue description to `docs/lessons/XX-lesson-name/SPEC.md`. This is the only file the Coder agent (codex, or any other tool acting as the Coder) reads to know what to do — it has no MCP access to Linear (see [ADR-0004](../../docs/adr/0004-mcp-single-writer-for-coder-agent.md) and `docs/workflow/AGENT-MODEL.md`). Only Claude can edit this file; if the Linear issue is updated later, update `SPEC.md` at the same time.

### 7. Move the issue to In Progress

Update the issue state via Linear MCP. (If GitHub integration is enabled, step 4 also does this automatically — re-updating is harmless since it is the same value.)

Note: the Linear update steps (steps 3, 6, 7) can only be done by Claude Code — the Coder agent (whether it is codex or any other tool) has no MCP connection to Linear (see `docs/workflow/AGENT-MODEL.md`), so it cannot run this skill on its own.

### 8. Report to the user

Reply concisely in Vietnamese:

- Which lesson, which branch, where the note is, where `SPEC.md` is located
- Lesson objectives (3–5 bullet points)
- The next command to type: `/teach <topic>`

## Linear issue description format

```markdown
## 🎯 Learning objectives

- <3-5 measurable bullets>

## 📚 Official documentation

- [<section name>](../../../../../.claude/skills/lesson-start/<full docs.nestjs.com link>)

## 🔗 Connect to prior knowledge

- Express/Prisma/hexagonal: <comparison>

## 🛠 Hands-on

<what code, in which file, how to verify>

## ✅ Definition of Done

- [ ] Lesson note has complete Connect to prior knowledge + Sources sections
- [ ] Hands-on runs successfully
- [ ] Tests pass
- [ ] Passed the quiz at the review step
- [ ] PR has passing CI and has been merged
```

## Boundaries

- **Do not** write code in `src/` — this is the lesson opening step, not the implementation step.
- **Do not** commit anything. Only create the branch and note file.
- **Do not** rename the Linear branch to make it "look better".
- Only Claude can edit `SPEC.md` — the Coder agent (codex or any other tool acting in that role) can only read it.
