# ADR-0002: Linear is the single source of truth for tasks, with native integration with GitHub and Slack

- **Status:** Accepted
- **Date:** 2026-08-10
- **Decision maker:** Hien Duong

## Context

This learning project needs a place to manage ~26 lesson with full description, organized by phase, with priorities and estimate. At the same time, the learner wants to get familiar with **the tools and processes that a real backend team uses**, not just a TODO file.

There are 4 related systems: PM tool, GitHub (code + CI), Slack (notifications), Notion (knowledge base). The biggest risk when using multiple systems is **misaligned information** — a task is marked as "in progress" while the corresponding PR was merged last week.

## Decision

1. **Linear is the single source of truth for task status.** No other system is considered authoritative for whether a lesson is completed or not.
2. Enable Linear's native **GitHub integration** and **Slack integration**. Task status updates are triggered **by git events**, not manual clicks:
   - Create a branch using the name generated by Linear → the issue automatically moves to _In Progress_
   - A PR with `Fixes NES-XX` is merged → the issue automatically moves to _Done_
3. The agent only automates the parts that integration cannot handle: writing lesson note, compiling the Notion hub, sending learning digests.
4. `docs/ROADMAP.md` is an offline projection, **not** the single source of truth.

## Considered Alternatives

| Option                                   | Pros                                                                                                                                                                                    | Cons                                                                                     | Reason for not selecting                          |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------ |
| **Linear + native integration** _(selected)_ | The Initiative→Project→Issue→Sub-issue model is sufficient to represent the curriculum; cycles show actual velocity; official MCP allows the agent to create/update tasks; GitHub/Slack integration is native | Requires an additional account; free tier has limits                                                 | —                                          |
| **GitHub Issues + Projects v2**             | No external tools needed; closest to PRs                                                                                                                                                  | Lacks standard cycles/estimates; does not provide a dedicated PM tool experience — something every company has | Misses part of the learning objective          |
| **Trello**                                  | Intuitive, easy to get started with                                                                                                                                                                 | No auto-transition based on PRs; no branch naming convention; shallow integration                  | Manual updates required → guaranteed misalignment      |
| **Notion database as PM**                  | Combines tasks and knowledge in one place                                                                                                                                                          | No proper git integration; Notion excels at documentation, not issue tracking       | Use Notion for its strengths: knowledge base |

## Consequences

**Positive**

- No manual "update task" step → no possibility of status misalignment. This is exactly why real teams invest in integration instead of relying on the discipline of manual updates.
- Develop an important habit: **branch names and PR descriptions are data, not decorative text**. If written correctly, the entire system runs automatically.
- You get real data about your own work: how many points you complete per cycle, how much your estimates are off.

**Tradeoffs**

- Depends on correct branch naming. If named incorrectly, automation breaks, and there are no visible errors → hard to detect. This is clearly documented in [WORKFLOW.md](../workflow/WORKFLOW.md).
- Linear's free tier limits the number of open issues; if you hit the limit, create issues per phase instead of creating them all at once.
- Four systems is a lot for a solo learner. This is acceptable, as experiencing multiple systems simultaneously is one of the key objectives.

**Next Steps**

- Enable GitHub + Slack integration in Linear Settings immediately after creating the repo and channel.
- The `/sync-progress` skill is only for supplementary work, **not** for re-updating what the integration has already handled — doing both would create two sources of truth, which is exactly what this ADR aims to avoid.
