# AGENTS.md — General Contract for All AI Agents

> All agents (Claude Code, codex, opencode, or any other agents) **must read this file before working** in the repo.
> Claude Code has additional separate instructions in `CLAUDE.md`.

## Project Context

This is a **NestJS learning project**, not a commercial product. The user is a beginner backend developer (already familiar with basic Node.js / Express / Prisma / hexagonal architecture), learning NestJS 11 following `docs.nestjs.com`. The final course project is a **Task Management API** (User / Project / Task / Comment).

This changes how agents should behave: **the goal is for the learner to make progress, not to complete tasks quickly.**

## Two Absolute Rules

1. **Do not write hands-on code for the learner** unless explicitly assigned (issues with the `agent:codex` label or the corresponding label for other tools holding the Coder role, or direct user request). By default: give suggestions, point out errors, ask questions — do not provide complete code.
2. **No agent may review its own code.** Code generated by an agent must go through a PR to be reviewed by another agent (or the user). The reason is documented in `docs/workflow/AGENT-MODEL.md`.

## Role Assignment

There are two **fixed roles**, not two fixed tool lists — any tool that fills the "Coder" role must follow the same standard:

| Role                        | Who holds it                                                                                     | Boundaries                                      |
| -------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| **Mentor · PM · Reviewer** | Always Claude Code (fixed — reason documented in `docs/workflow/AGENT-MODEL.md`)                 | No hands-on coding; no PR merging            |
| **Coder**                  | codex (default) — occasionally other agents (opencode, Hermes...) when a comparative version is needed | Branch `<tool>/nes-XX-...`; all output goes through PR |

**MCP:** Only Claude Code connects to Linear/Notion/Slack/Postman. Any tool holding the Coder role **must not** configure these MCP servers — receive specs via the `docs/lessons/XX-*/SPEC.md` file (generated by Claude Code at the `/lesson-start` step), do not query Linear directly. Reason: [ADR-0004](docs/adr/0004-mcp-single-writer-cho-coder-agent.md).

## Commands

```bash
pnpm install            # Install dependencies according to pnpm-lock.yaml
pnpm start:dev          # Dev mode, watch mode
pnpm build              # Nest build outputs to dist/
pnpm lint               # ESLint --fix
pnpm format             # Prettier --write
pnpm test               # Unit tests
pnpm test:e2e           # E2E tests
pnpm test:cov           # Coverage
pnpm verify                 # Matches what CI runs — use before opening a PR
pnpm db:up / db:down    # PostgreSQL + Redis via Docker Compose
```

**The package manager is pnpm.** Using npm or yarn will create a second lockfile and break CI.

## Coding Style

- TypeScript + NestJS decorators + DI. Dependencies are injected via **constructor injection**, no manual `new`, no global singleton imports.
- Layer separation: `*.controller.ts` only handles HTTP · `*.service.ts` holds business logic · `*.module.ts` ties everything together. **Business logic must not be placed in controllers.**
- Follow Nest naming standards: `TasksController` in `tasks.controller.ts`, `TasksService` in `tasks.service.ts`, `TasksModule` in `tasks.module.ts`.
- Prettier: single quotes, trailing commas. Prettier handles formatting for `.ts`, `.json`, `.md`, `.yml` — **do not format manually**, run `pnpm format`.
- `tsconfig.json`: `strictNullChecks: true`, `noImplicitAny: false`. `no-explicit-any` is disabled in ESLint, but you should still **avoid `any`** — the reviewer will catch it.
- **CI runs `eslint --max-warnings=0`** → even warnings will break CI, including `no-floating-promises`.

## Testing

- Unit test `*.spec.ts` files are placed **next to** source files in `src/`. E2E tests are in `test/`, with the `.e2e-spec.ts` suffix.
- Use `Test.createTestingModule()` from `@nestjs/testing`.
- Tests should verify **behavior**, not just check if mocks were called. Always include error cases, not just the happy path.
- If behavior changes, you must update the corresponding tests. Run `pnpm test` before opening a PR.

## Commits & PRs

**Conventional Commits** — `commitlint` blocks non-compliant commits at the `commit-msg` git hook:

```
<type>(<scope>): <mô tả>

feat(tasks): add CRUD endpoints for tasks
docs(lesson-02): note về controllers và routing
chore: bump @nestjs/core to 11.1.28
```

Allowed types: `feat` `fix` `docs` `test` `refactor` `chore` `style` `perf` `revert`.

- Branches: use the **exact** name generated by Linear (`hien/nes-XX-...`). Coder agents use the tool name as prefix: `codex/nes-XX-...`, `opencode/nes-XX-...`, etc.
- PR descriptions must include `Fixes NES-XX` (for agent PRs, reference the assigned issue).
- Squash and merge. Do not push directly to `main` — branch protection is enabled.
- **Never use `git commit --no-verify`.** The hook is a quality gate, not an obstacle.

## Security & Configuration

- **Never commit secrets.** The `.env` file is already in `.gitignore`; only commit `.env.example` with dummy values.
- When adding new environment variables, you must add them to `.env.example` with explanatory comments.
- Validate input data (DTO + `ValidationPipe`) before passing it to the service.
- Do not log secrets, tokens, or passwords. Do not return `password`/`refreshToken` in responses.

## Looking Up NestJS Documentation

`docs.nestjs.com` is an Angular SPA — fetching HTML will **not** return the content. Get the original markdown:

```bash
gh api "repos/nestjs/docs.nestjs.com/contents/content/controllers.md" \
  -H "Accept: application/vnd.github.raw"
```

**Do not write NestJS code from memory when documentation is available.** For library versions: run `npm view <pkg> version`, do not guess.
