# AGENTS.md — Shared contract for all AI agents

> Every agent (Claude Code, codex, opencode, or any other agent) **must read this file before working** in the repository.
> Claude Code has additional specific instructions in `CLAUDE.md`.

## Project context

This is a **NestJS learning project**, not a commercial product. The user is a beginner backend developer (already familiar with Node.js / Express / Prisma / basic hexagonal architecture) learning NestJS 11 from `docs.nestjs.com`. The final course product is a **Task Management API** (User / Project / Task / Comment).

This changes how agents should behave: **the goal is learner progress, not finishing tasks quickly.**

## Two absolute rules

1. **Do not write hands-on code for the learner** unless explicitly assigned (an issue has the `agent:codex` label or the user asks directly). By default: offer hints, point out errors, and ask questions — do not provide complete code.
2. **No agent may review its own code.** Agent-generated code must go through a PR for another agent (or the user) to review. The rationale is in `docs/workflow/AGENT-MODEL.md`.

## Commands

```bash
pnpm install            # install dependencies from pnpm-lock.yaml
pnpm start:dev          # dev, watch mode
pnpm build              # nest build → dist/
pnpm lint               # eslint --fix
pnpm format             # prettier --write
pnpm test               # unit test
pnpm test:e2e           # e2e tests
pnpm test:cov           # coverage
pnpm verify                 # exactly what CI runs — use before opening a PR
pnpm db:up / db:down    # postgres + redis through docker compose
```

**The package manager is pnpm.** Using npm or yarn creates a second lockfile and makes CI fail.

## Coding style

- TypeScript + decorator + NestJS DI. Dependencies use **constructor injection**, no manual `new`, and no global singleton imports.
- Layering: `*.controller.ts` handles only HTTP · `*.service.ts` contains business logic · `*.module.ts` wires components together. **Business logic does not belong in controllers.**
- Follow Nest naming conventions: `TasksController` in `tasks.controller.ts`, `TasksService` in `tasks.service.ts`, `TasksModule` in `tasks.module.ts`.
- Prettier: single quote, trailing comma. Prettier manages formatting for `.ts`, `.json`, `.md`, `.yml` — **do not format manually**, run `pnpm format`.
- `tsconfig.json`: `strictNullChecks: true`, `noImplicitAny: false`. `no-explicit-any` is disabled in ESLint, but still **avoid `any`** — reviewers will flag it.
- **CI run `eslint --max-warnings=0`** → warnings also make CI fail, including `no-floating-promises`.

## Testing

- Unit tests `*.spec.ts` are placed **next to** source files in `src/`. E2E tests are in `test/`, with the suffix `.e2e-spec.ts`.
- Use `Test.createTestingModule()` from `@nestjs/testing`.
- Tests verify **behavior**, not only whether mocks were called. Always include error cases, not only the happy path.
- Behavior changes require test updates. Run `pnpm test` before opening a PR.

## Commit & PR

**Conventional Commits** — `commitlint` is enforced by the git hook `commit-msg`:

```
<type>(<scope>): <description>

feat(tasks): add CRUD endpoints for tasks
docs(lesson-02): notes on controllers and routing
chore: bump @nestjs/core to 11.1.28
```

Allowed types: `feat` `fix` `docs` `test` `refactor` `chore` `style` `perf` `revert`.

- Branch: use the **exact** name generated by Linear (`hien/nes-XX-...`). Agents use their own prefixes: `codex/...`, `opencode/...`.
- The PR description must contain `Fixes NES-XX` (an agent PR references its assigned issue).
- Squash and merge. Do not push directly to `main` — branch protection is enabled.
- **Never use `git commit --no-verify`.** Hooks are quality guardrails, not obstacles.

## Security & configuration

- **Never commit secrets.** The `.env` file is already in `.gitignore`; only commit `.env.example` with placeholder values.
- When adding an environment variable, also add it to `.env.example` with an explanatory comment.
- Validate data at the input boundary (DTO + `ValidationPipe`) before passing it to the service.
- Do not log secrets, tokens, or passwords. Do not return `password`/`refreshToken` in response.
