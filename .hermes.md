## 3. Approval gateway — the strictest rule

1. **DO NOT dispatch any agent before user approval.** Mandatory flow: Hermes proposes → user approves → then run.
2. Before dispatching, Hermes must announce in chat: agent, model, task, branch, workdir, limits (max-turns/budget), and verification method.
3. Agents run on **dedicated branches** (`codex/nes-XX-...`, `opencode/nes-XX-...`) — never on main, never on lesson branches `hien/...`.
4. Agents **must not**: push directly to main, merge, open PRs outside the approved workflow, or modify files outside their scope.
5. Agent output is merged into main only via **dedicated PRs** (ADR-0005): Claude Code **local review** → Codex-action review (layer 1, automated, `codex-review.yml`) → lead review by the user → squash merge. **Copilot CLI is NOT automatic** — it is only dispatched for large MRs (`mr/*`, max 2/day, see `docs/workflow/REVIEW-MODEL.md`).
6. No agent may review its own code.
7. **Hermes does not merge — only the user (Hien Duong) finalizes merges.** Claude Code does not merge either.

## 5. Standard operating flow (per task)

1. User submits request → Hermes classifies per the routing table, proposes (agent + model + task + branch + limits).
2. User approves → Hermes dispatches **the exact command the user would run themselves** (no proxy wrapping, no model changes, no added layers — non-interference).
3. Agent reads AGENTS.md + SPEC before working; commits include the tool's `Co-authored-by` trailer (see section 9).
4. When agent finishes → Hermes **independently verifies**: git log/status, reads the full diff, runs `pnpm verify` — do not trust self-reported results.
5. Hermes opens PR (description must include `Fixes NES-XX`) → **mentions @TheHienDuong** → **Claude Code local review** → **Codex-action review** (automated, code-quality layer, every PR) → user is the lead reviewer → **only the user merges** (with mandatory approval from code owner `@hienduong-agilityio`). For large MRs (`mr/*`): add **Copilot gatekeeper review** (dispatched via herdr, max 2/day) before the user merges.
6. Squash merge → Hermes sends a summary + logs 1 line to `docs/lessons/_agent-log.md` (only when the user reports the merge / Hermes is asked — no background daemon).

## Herdr bridge (PTY-pane dispatch)

> Approved by the user on 2026-08-14 (ADR-0006). A second dispatch method alongside exec/print-mode (§5.1).

**Principle:** the pane is for the HUMAN to see & intervene; the filesystem is for the MACHINE to know it's done.

**9-step flow:**

1. `hermes kanban create/claim` — task state (the single source of truth)
2. `herdr worktree create --cwd <repo> --branch codex/nes-XX-... --label NES-XX --json` — auto-creates a workspace + tab + pane, cwd = worktree
3. `herdr agent start <name> --kind codex --pane <pane_id> --timeout 60000` — one ephemeral agent per task (prevents context pollution)
4. `herdr agent prompt <pane_id> "<task> + MUST write <worktree absolute path>/.hermes/runs/NES-XX.json (nonce, git rev-parse HEAD, result)"`
5. Hermes **polls the JSON file = the only verdict**. `pane wait-output --match` with a string that appears in the prompt is FORBIDDEN (proven false positive on 2026-08-14); `herdr agent wait` does not track turns → do not use it as the done verdict
6. Independent verify: RAW `git diff` + `pnpm verify` — do not trust the self-report
7. Dedicated PR `Fixes NES-XX` + trailer → **Claude Code local review** → Codex-action review (automated) → **user merge** (ADR-0005 unchanged); if later bundled into a large MR `mr/*` → add a Copilot gatekeeper review before "release" (ADR-0008)
8. `hermes kanban complete`
9. Cleanup: `herdr worktree remove --workspace <id> --force` + `git branch -D <branch>`

**Commands verified 2026-08-14:** worktree create auto-creates workspace/tab/pane; `pane split --pane <id> --direction right --cwd <path>`; `agent start --kind codex` (interactive_ready); `agent prompt` sends successfully (do not trust `--wait` for done); `worktree remove --workspace <id> --force`; note `tab close` fails "last tab" → use worktree remove / workspace close instead.

**Guardrail:**

- Resolve the target dynamically with `herdr agent list` before every dispatch — do not trust an old label/pane id (pane drift has actually happened)
- Cap of 2-3 concurrent worker panes — more than that and the human can't keep up with approvals
- Do not touch the pane where Claude Code is currently running (currently: w1:p1)
- `herdr agent read` is only for diagnosing a blocked/failed run — never use it to fetch the result
- Official profiles: **coder-codex** (Coder) · **mentor-claude** (Mentor/PM/Reviewer local) · **reviewer-copilot** (Gatekeeper for large MRs — `mr/*` only) · **writer** (docs). `coder-agy`, `coder-fast`, `reviewer-gate`: archived — do not use in the standard flow
- Dispatch via Herdr must still go through the approval gateway §3 — no exceptions

## 8. Technical contract (inherits from AGENTS.md/CLAUDE.md)

- Package manager: **pnpm** only. Before opening a PR or reporting completion: run `pnpm verify` (lint --max-warnings=0 + prettier check + test + build).
- Use Conventional Commits; commitlint blocks at the hook — **never** use `--no-verify`.
- Branches use the exact Linear name (`hien/nes-XX-...`); PRs must include `Fixes NES-XX`; squash merge; do not push directly to main (ruleset `protect-main`).
- NestJS: business logic lives in services, controllers only handle HTTP, DI via constructor injection. Enable `strictNullChecks`, avoid `any`.
- Tests: `*.spec.ts` next to src, e2e tests in `test/`; test behavior + always include error cases.
- Documentation: `docs.nestjs.com` is an Angular SPA → get raw markdown via `gh api repos/nestjs/docs.nestjs.com/contents/content/<file>.md`. Library version: use `npm view <pkg> version`, do not guess.
- Language: reply and write documentation in **Vietnamese**, keep English terminology (provider, guard, interceptor, pipe, DI, decorator).
- Remotes: origin = GitHub (work remote), gitlab = company repo — **do not touch gitlab**.
- **Bilingual:** every docs task → require the agent to create/update both versions (vi/en): `main` in Vietnamese, `example/nestjs-training` in English. Hermes verification adds a step: diff the 2 branches (must be empty apart from language) + scan the EN version for Vietnamese characters. GitLab only syncs the EN version, author = `hienduong-agility`, no trailer.

## 9. GitHub attribution — who does what task (format matching Claude)

Each tool commits using the exact format Claude Code uses: author = user, with `Co-authored-by: <Tool> <model> <email>` trailer — GitHub renders the trailer as an icon (avatar) + name + link to the bot account:

| Tool        | Trailer (Co-authored-by)                                                                | Bot account on GitHub                              |
| ----------- | --------------------------------------------------------------------------------------- | -------------------------------------------------- |
| **Hermes**  | `Co-authored-by: Hermes <model> <259144110+hermes-agent[bot]@users.noreply.github.com>` | `hermes-agent[bot]` (github.com/apps/hermes-agent) |
| codex       | `Co-authored-by: Codex <codex@openai.com>` (added automatically by codex)               | codex bot                                          |
| Claude Code | `Co-authored-by: Claude <noreply@anthropic.com>` (added automatically)                  | Claude bot                                         |
| opencode    | `Co-authored-by: opencode <noreply@opencode.ai>` (added automatically)                  | opencode bot                                       |

Rules:

- Hermes commit author = user's git config (**DO NOT override**) — exactly like Claude: the user is responsible, the bot gets credit.
- Hermes must add the trailer to **both the commit message and PR body** (squash merge uses title + body as the commit message — a trailer only in the commit message will be lost on merge):

  ```
  Co-authored-by: Hermes <model-name> <259144110+hermes-agent[bot]@users.noreply.github.com>
  ```

- Model name in the trailer = session model ID (e.g. `deepseek-v4-flash`) — matching how Claude Code records the model name.
- **NEVER** set repo-local / global `user.name` / `user.email` for the bot — this will steal the user's identity (user hands-on commits must retain personal identity).
- After squash merge, the merged commit shows both the author (user) + co-author (`hermes-agent[bot]` with avatar + link) — sufficient data for graphs/contributors, blame, and commit history.
