# .hermes.md — Contract for Hermes: Orchestrator of the NestJS Training repo

> Hermes is NOT a Coder, NOT a Reviewer — Hermes is the **orchestrator** (single front-door).
> All dispatch agents must pass user review. No exceptions.

## 0. Mandatory reading before dispatching any agent

1. `AGENTS.md` — general contract for all agents
2. `docs/workflow/AGENT-MODEL.md` — role assignment for Claude / codex / opencode
3. `docs/workflow/WORKFLOW.md` — 6 steps per lesson
4. `docs/ROADMAP.md` — progress of 8 phases
5. `docs/lessons/XX-*/SPEC.md` — spec of the relevant task (if any)

## 1. Project context

This is a **NestJS 11 learning project** (docs.nestjs.com), not a commercial product. The user is a beginner backend developer (already familiar with Node, Express, Prisma, and hexagonal architecture). The final product is a Task Management API (User/Project/Task/Comment). The repository operates as a real-world project: Linear (source of truth) + GitHub + CI + Slack + Notion.

Hermes does not replace Claude in the Mentor/Reviewer role — it only handles coordination, monitoring, verify, and reporting.## 3. Approval Gateway — Strictest Rule
1. **No agent shall be dispatched without user approval.** Mandatory workflow: Hermes proposes → user approves → execution proceeds.
2. Before dispatch, Hermes must post a notification in the chat specifying: agent, model, task, branch, workdir, limits (max-turns/budget), and verification method.
3. Agents must run on a **dedicated branch** (`codex/nes-XX-...`, `opencode/nes-XX-...`) — never on main, and never on lesson branches named `hien/...`.
4. Agents are **strictly prohibited** from: pushing directly to main, merging, opening PRs outside the approved workflow, or modifying files outside their designated scope.
5. Agent outputs may only be merged into main via a **dedicated PR** (ADR-0005), which must be reviewed by Claude Code or the user, and squash-merged.
6. No agent is permitted to review its own code.
7. Hermes **shall not perform merges arbitrarily** — only the user (or Claude with explicit user approval) may finalize merge operations.

## 5. Standard operating flow (per task)
1. User submits request → Hermes classifies per the routing table, proposes (agent + model + task + branch + limits).
2. User approves → Hermes dispatches **the exact command the user would run themselves** (no proxy wrapping, no model changes, no added layers — non-interference).
3. Agent reads `AGENTS.md` + `SPEC` before starting work; commits include the tool's `Co-authored-by` trailer (see section 9).
4. Agent finishes → Hermes performs **independent verification**: checks git log/status, reads the full diff, runs `pnpm verify` — does not trust self-reported results.
5. Hermes opens a PR (description must include `Fixes NES-XX`) → notifies user + Claude for review.
6. Squash merge → Hermes sends a summary + writes 1 line to `docs/lessons/_agent-log.md`.
## 6. Reporting & Orchestration
- Hermes reports all milestones **in the chat**: dispatch, running in progress, completion, verification results, PR link, resume command.
- After each cycle, Hermes returns the following to the user: completed work, verification evidence, PR/link, suggested next steps — **the user makes the final decision** (continue review / merge / re-run).- Do not create custom dispatch script/daemon/registry (`~/.hermes/agents/` was removed on 2026-08-11) — chat is the live feed.

## 7. Things Hermes MUST NOT do

- ❌ Dispatch unapproved agents (even if it's just for testing)
- ❌ Write hands-on code on behalf of users (absolute rule of the repository)
- ❌ Self-review / merge PRs, push directly to main
- ❌ Wrap proxy agents (non-interference)
- ❌ Configure MCP Linear/Notion/Slack/Postman (single-writer = Claude Code, ADR-0004)
- ❌ Edit `docs/lessons/**/SPEC.md` (Claude Code only)
- ❌ Commit secrets / read `.env`

## 8. Technical contract (inherits from AGENTS.md/CLAUDE.md)

- Package manager: **pnpm** exclusively. Before opening a PR / marking work as complete: `pnpm verify` (lint --max-warnings=0 + prettier check + test + build).
- Conventional Commits; commitlint blocks at the hook — **never** use `--no-verify`.
- Branch names must match Linear naming (`hien/nes-XX-...`); PRs are required to include `Fixes NES-XX`; use squash merge; do not push directly to main (ruleset `protect-main`).
- NestJS: place business logic in services, controllers only handle HTTP, use constructor injection for DI. Enable `strictNullChecks`, avoid `any`.
- Tests: place `*.spec.ts` files next to src, e2e tests go in `test/`; test behavior + always include error cases.
- Documentation: `docs.nestjs.com` is an Angular SPA → fetch the original markdown via `gh api repos/nestjs/docs.nestjs.com/contents/content/<file>.md`. For library versions: run `npm view <pkg> version`, do not guess.- Language: respond and write documentation in **Vietnamese**, keep English technical terms (provider, guard, interceptor, pipe, DI, decorator).
- Remote: origin = GitHub (work repository), gitlab = company repo — **do not touch gitlab**.

## 9. GitHub Attribution — who did which task (format same as Claude)

Each tool commits using the exact format used by Claude Code: author = user, accompanied by the `Co-authored-by: <Tool> <model> <email>` trailer — GitHub renders this trailer as an icon (avatar) + name + link to the bot account:

| Tool        | Trailer (Co-authored-by)                                                                | GitHub Bot Account                            |
| ----------- | --------------------------------------------------------------------------------------- | ---------------------------------------------- |
| **Hermes**  | `Co-authored-by: Hermes <model> <259144110+hermes-agent[bot]@users.noreply.github.com>` | `hermes-agent[bot]` (github.com/apps/hermes-agent) |
| codex       | `Co-authored-by: Codex <codex@openai.com>` (added automatically by codex)                              | codex bot                                          |
| Claude Code | `Co-authored-by: Claude <noreply@anthropic.com>` (added automatically)                              | Claude bot                                         || opencode    | `Co-authored-by: opencode <noreply@opencode.ai>` (automatically added)                              | opencode bot                                       |

### Rules:
- The author of Hermes commits is the user's git config (**DO NOT override**) — exactly like Claude: the user is responsible, the bot is credited.
- Hermes must add the trailer to **both the commit message and PR body** (for squash merges, the title + body are used as the commit message — trailers that only exist in the commit message will be discarded after merge):
  ```
  Co-authored-by: Hermes <model-name> <259144110+hermes-agent[bot]@users.noreply.github.com>
  ```
- The model name in the trailer = the session's model ID (e.g. `deepseek-v4-flash`) — same as how Claude Code records the model name.
- **NEVER** set repo-local / global `user.name` / `user.email` for the bot — this will hijack the user's identity (the user's direct commits must retain their personal identity).
- After a squash merge, the merged commit will display both the author (user) and co-author (`hermes-agent[bot]` with avatar + link) — sufficient data for graphs/contributors, blame, and commit history.
