## 3. Cổng kiểm duyệt — quy tắc nghiêm ngặt nhất

1. **Không dispatch agent nào khi chưa được user duyệt.** Luồng bắt buộc: Hermes đề xuất → user duyệt → mới chạy. Dispatch qua Herdr pane cũng phải qua đúng luồng trên — không ngoại lệ.
2. Trước khi dispatch, Hermes báo trong chat: agent, model, task, branch, workdir, giới hạn (max-turns/budget), cách verify.
3. Agent chạy trên **branch riêng** (`codex/nes-XX-...`, `agy/nes-XX-...`) — không bao giờ trên main, không trên branch lesson `hien/...`.

5. Output agent chỉ vào main qua **PR riêng** (ADR-0005): Claude Code **review local** → Codex GitHub App connector review (lớp 1, tự động, `chatgpt-codex-connector[bot]`) → lead review bởi user → squash merge. **Copilot CLI KHÔNG chạy tự động** — chỉ dispatch cho MR lớn (`mr/*`, tối đa 2/ngày, xem `docs/workflow/REVIEW-MODEL.md`).
6. Không agent nào tự review code của chính nó.
7. **Hermes không merge — chỉ user (Hien Duong) chốt merge.** Claude Code cũng không merge.

## 5. Luồng vận hành chuẩn (mỗi task)

3. Agent đọc AGENTS.md + SPEC trước khi làm; commit kèm trailer `Co-authored-by` của tool đó (xem mục 9).
4. Agent xong → Hermes **verify độc lập**: git log/status, đọc toàn bộ diff, chạy `pnpm verify` — không tin lời tự báo cáo.
5. Hermes mở PR (description bắt buộc có `Fixes NES-XX`) → **mention @TheHienDuong** → **Claude Code review local** → **Codex GitHub App connector review** (tự động, lớp code-quality, mọi PR) → user là lead reviewer cuối → **chỉ user merge** (kèm approve bắt buộc của code owner `@hienduong-agilityio`). 6. Squash merge → Hermes báo tổng kết + ghi 1 dòng vào `docs/lessons/_agent-log.md` (chỉ khi user báo đã merge / Hermes được hỏi, không tự chạy ngầm) → **dọn dẹp bắt buộc** workspace/worktree/pane + branch local của task đó (xem mục "Dọn dẹp bắt buộc" bên dưới) — không đợi user nhắc.

## Dọn dẹp bắt buộc — workspace/worktree/pane/branch sau khi task xong

> Bắt buộc, không phải tùy chọn. Áp dụng cho mọi task dispatch qua Herdr (worktree riêng cho Coder/agy). Ngay sau khi task/PR **hoàn tất dứt điểm** (đã squash merge vào main) hoặc **bị hủy rõ ràng** (user báo bỏ task, đóng PR không merge, đóng issue), Hermes phải dọn workspace/worktree/pane Herdr đã dùng cho task đó và xóa branch local tương ứng — không để lại worktree vô dụng chiếm chỗ.

**Khi nào chạy — ngay lập tức, không đợi nhắc lại:**

- Ngay sau khi user báo đã squash merge PR (hoặc Hermes tự verify branch đã nằm trong lịch sử `main`).
- Ngay sau khi user báo hủy/bỏ task (đóng issue Linear, đóng PR không merge, đổi hướng công việc).

**Resolve target động — bắt buộc trước khi xóa bất cứ gì (không tin label/id cũ):**

1. `herdr agent list` — lấy danh sách workspace/worktree/pane hiện tại, không dùng lại id/label đã ghi từ lúc dispatch (pane/workspace drift đã xảy ra thật, xem guardrail bên dưới).
2. `git status` tại đúng worktree — xác nhận không còn uncommitted changes.
3. Kiểm tra trạng thái PR (`gh pr view <branch> --json state,mergedAt`) và trạng thái issue Linear trước khi xóa branch — branch phải đã merge hoặc PR đã đóng dứt điểm.

**Ngoại lệ an toàn — KHÔNG BAO GIỜ xóa nếu rơi vào một trong các trường hợp sau:**

- Worktree `main` hoặc worktree hiện tại của user (đang mở/đang dùng để làm việc).
- Worktree lesson/coder/reviewer đang **active** (task chưa đóng, đang trong vòng review local hoặc chờ CI/PR).
- Worktree còn **uncommitted changes** (`git status` không sạch) — không bao giờ xóa mất việc chưa lưu.
- Branch còn **PR đang mở** (chưa merge, chưa đóng).
- Pane đang **chạy** hoặc còn cần cho việc khác (agent chưa xong turn, user đang theo dõi/tương tác).

**Remote branch:** Mặc định **không** xóa branch trên remote (`origin`) — chỉ xóa **local branch** (`git branch -D`). Chỉ xóa remote branch khi user **yêu cầu rõ ràng, riêng biệt** cho lần đó.

**Nếu bị chặn:** Báo đúng lý do chặn trong chat (ví dụ: "còn uncommitted changes ở worktree X", "PR #NN vẫn đang mở", "pane Y đang chạy agent") — không ép xóa, không âm thầm bỏ qua bước dọn dẹp. Thử lại dọn dẹp ngay khi điều kiện chặn được giải quyết (PR merge/đóng, agent chạy xong, user commit hoặc discard xong).

**Lệnh dọn (chỉ chạy sau khi đã pass hết các check ở trên):**

```bash
herdr worktree remove --workspace <id> --force
git branch -D <branch>
```

## Herdr bridge (PTY-pane dispatch)

> Được user duyệt 2026-08-14 (ADR-0006). Cách dispatch thứ hai bên cạnh exec/print-mode (§5.1).

**Nguyên tắc:** pane để NGƯỜI thấy & can thiệp; filesystem để MÁY biết đã xong.

**Luồng 9 bước:**

1. `hermes kanban create/claim` — task state (nguồn sự thật duy nhất)
2. `herdr worktree create --cwd <repo> --branch codex/nes-XX-... --label NES-XX --json` — tự tạo workspace + tab + pane, cwd = worktree
3. `herdr agent start <name> --kind codex --pane <pane_id> --timeout 60000` — agent ephemeral per task (chống context pollution)
4. `herdr agent prompt <pane_id> "<task> + BẮT BUỘC ghi <worktree tuyệt đối>/.hermes/runs/NES-XX.json (nonce, git rev-parse HEAD, kết quả)"`
5. Hermes **poll file JSON = phán quyết duy nhất**. CẤM `pane wait-output --match` với chuỗi có trong prompt (false positive đã chứng minh 2026-08-14); `herdr agent wait` không track turns → không dùng làm phán quyết done
6. Verify độc lập: `git diff` RAW + `pnpm verify` — không tin lời tự báo cáo
7. PR riêng `Fixes NES-XX` + trailer → **Claude Code review local** → Codex GitHub App connector review (tự động) → **user merge** (ADR-0005 giữ nguyên); nếu gộp vào MR lớn `mr/*` sau đó → thêm Copilot gatekeeper review trước khi "phát hành" (ADR-0008)
8. `hermes kanban complete`
9. **Dọn dẹp bắt buộc** (xem mục "Dọn dẹp bắt buộc — workspace/worktree/pane/branch sau khi task xong" ở trên) — không phải bước tùy chọn: resolve target động bằng `herdr agent list`, check `git status` + trạng thái PR, rồi mới `herdr worktree remove --workspace <id> --force` + `git branch -D <branch>`. Bỏ qua ngoại lệ an toàn (uncommitted changes, PR mở, pane đang chạy) thì báo blocker, không ép xóa.

**Lệnh đã verify 2026-08-14:** worktree create tự tạo workspace/tab/pane; `pane split --pane <id> --direction right --cwd <path>`; `agent start --kind codex` (interactive_ready); `agent prompt` gửi được (không tin `--wait` cho done); `worktree remove --workspace <id> --force`; lưu ý `tab close` fail "last tab" → dùng worktree remove / workspace close.

## 8. Hợp đồng kỹ thuật (kế thừa AGENTS.md/CLAUDE.md)

- Package manager: **pnpm** duy nhất. Trước khi mở PR / báo xong: `pnpm verify` (lint --max-warnings=0 + prettier check + test + build).
- Conventional Commits; commitlint chặn tại hook — **không bao giờ** dùng `--no-verify`.
- Branch lấy đúng tên Linear (`hien/nes-XX-...`); PR bắt buộc `Fixes NES-XX`; squash merge; không push thẳng main (ruleset `protect-main`).
- NestJS: business logic trong service, controller chỉ HTTP, DI qua constructor injection. `strictNullChecks` bật, tránh `any`.
- Test: `*.spec.ts` cạnh src, e2e trong `test/`; test hành vi + luôn có case lỗi.
- Tài liệu: `docs.nestjs.com` là Angular SPA → lấy markdown gốc bằng `gh api repos/nestjs/docs.nestjs.com/contents/content/<file>.md`. Version lib: `npm view <pkg> version`, không đoán.
- Ngôn ngữ: trả lời và viết tài liệu bằng **tiếng Việt**, giữ thuật ngữ tiếng Anh (provider, guard, interceptor, pipe, DI, decorator).
- Remote: origin = GitHub (nơi làm việc), gitlab = repo công ty — **không đụng gitlab**.
- **Bilingual:** mọi task docs → yêu cầu agent tạo/cập nhật cả 2 bản vi/en (`main` tiếng Việt, `example/nestjs-training` tiếng Anh). Verify của Hermes thêm bước: so diff giữa 2 branch (phải rỗng ngoài ngôn ngữ) + scan ký tự tiếng Việt trên bản EN. GitLab chỉ sync bản EN, author = `hienduong-agility`, không kèm trailer.
